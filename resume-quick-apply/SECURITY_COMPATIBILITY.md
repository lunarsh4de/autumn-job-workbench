# 对抗式审查与兼容性说明（0.12.2）

## 已修复问题

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| 高 | 扩展原本在所有网站常驻并申请 `<all_urls>`，安装警告较强，攻击面过大 | 移除常驻内容脚本和永久站点权限；用户点击扩展后，以 `activeTab + scripting` 只注入当前 HTTP(S) 页面 |
| 高 | 网页 CSS 可改变或隐藏悬浮助手的内部布局 | 悬浮 UI 放入开放式 Shadow DOM，网页普通样式不再进入组件内部 |
| 中 | 安装后已打开的网页没有内容脚本，必须刷新才能填充 | 消息连接失败时按需注入 `data.js` 与 `content.js`，随后自动重试一次 |
| 中 | 重复注入可能注册多个监听器并重复执行操作 | 增加同一页面上下文的幂等加载标记 |
| 中 | Windows PowerShell 5 按系统编码读取 UTF-8 Manifest，中文可能导致 JSON 解析失败 | 安装助手显式使用 UTF-8 读取 Manifest，并提供只校验模式和复制验证模式 |
| 中 | 首次打开直接显示空的投递页，用户不知道先配置资料 | 空资料时自动进入资料标签，并显示首次设置提示 |
| 低 | 长预览提示曾覆盖下方内容，悬浮面板曾向按钮下方展开 | 状态提示改为正常文档流；面板固定在按钮上方并做桌面、窄屏边界检查 |
| 中 | 快捷键可能在用户未查看页面时触发附件上传 | 快捷键和右键入口默认剔除附件；只有用户主动开启“快捷填充时选择附件”后才传递附件 |
| 中 | 后台快捷入口可能绕过弹窗的按需注入和状态校验 | 后台复用相同的 HTTP(S) 限制、资料校验、按需注入和单次重试流程，并通过徽标及页面提示反馈结果 |
| 低 | 新设置和结构化经历可能破坏旧备份兼容性 | 使用 schema v3 导出，导入端同时接受 v1/v2/v3；旧备份缺省经历为空、快捷附件关闭 |
| 高 | 旧版 PDF/DOCX 解析依赖存在公开漏洞 | 使用 PDF.js 6.3.289 与 Mammoth 1.11.0，生产依赖审计为 0 个已知漏洞；只把本地字节传给解析器 |
| 中 | DOCX 空段落可能被误判为大量独立经历 | 改为按日期区间聚合，使用真实 DOCX/PDF 在 Edge 中复测出一致的 3 段工作、1 段教育、7 段项目 |
| 中 | 自动分类覆盖用户已经整理的资料 | 导入先展示数量预览，默认只补空字段并追加去重经历；覆盖必须显式勾选 |
| 中 | 多段经历字段可能串位 | 仅在唯一经历分区上下文中匹配，并按同类字段 DOM 顺序映射；不自动点击网站“新增经历”按钮 |
| 中 | 双语姓名和无标题教育区会漏识别或错位 | 姓名候选限制在页首三行并支持中英混排；缺少教育标题时按工作区之前的日期锚点推断，学校/专业/学位按三行布局拆分 |
| 中 | 解析失败后旧预览仍可被误应用 | 每次新选择立即清空候选和预览；取消操作也使未完成读取失效 |
| 中 | 先选慢文件再选快文件会被旧结果反向覆盖 | 为每次读取分配递增请求号，只允许最后一次选择更新预览 |
| 中 | 未建模栏目被追加到最后一段项目 | 奖项、证书、语言、校园经历、志愿、培训和出版物等标题作为强制分区边界 |
| 中 | Moka 深层标签和合并文本框可能无法映射 | 向上读取有限范围的视觉标签；赛事、获奖、语言、论文/期刊单独建模，并支持“语言证书及成绩”整组填写 |
| 中 | 点击“预览并提交”可能被误当成已投递 | 监听提交意图后记录页面成功状态快照，只接受之后新增或变化的明确成功文案；同 URL 24 小时去重 |
| 低 | 投递记录难以迁移、统计或可能被误清空 | 记录页提供本地 UTF-8 BOM CSV 导出；导出不上传数据，清空前要求二次确认 |
| 中 | 单独年份的比赛或获奖记录被合并、年份丢失 | 比赛和获奖增加独立年份字段；按“年份”切分连续条目，并保留用户确认前的解析预览 |
| 中 | 校园经历被当作未建模边界丢弃 | 增加校园经历结构化模型，支持组织/活动、职务、日期和描述，并映射 Moka 深层标签 |
| 低 | 只显示逐条记录，难以查看已投公司；30 条上限不利于长期导出 | 增加公司聚合视图和独立公司 CSV；本地最多保留 500 条，界面仅渲染最近 30 条以控制性能 |
| 中 | 招聘平台名被误记录为公司，或元数据空格造成重复公司 | 忽略 Moka/Mokahr 等通用平台名，修剪元数据；无有效元数据时从招聘域名归一化公司名称 |
| 中 | 自动记录因本地存储失败而无可见补救路径 | 自动挂载页面状态提示并明确引导用户点击“标记已投递”手动重试；失败不写入虚假记录 |

项目自有运行时代码未使用 `fetch`、XHR、WebSocket 或 `sendBeacon`。PDF.js 内含通用文档加载能力，但插件只向它传入用户选择文件的 `Uint8Array`，未传入 URL；扩展也没有永久站点权限。个人资料只写入 `chrome.storage.local`，分类导入和备份导入导出都由用户主动触发。

新增的 `contextMenus` 权限只创建当前普通网页上的用户操作菜单。扩展仍无 `host_permissions`、无静态 `content_scripts`，不会恢复全站常驻访问。

## 仍然存在的边界

- 简历控件触发 `change` 后，招聘网站可能立即把附件发送到其服务器。插件无法撤销服务器已经收到的数据。
- iframe、封闭式 Shadow DOM、自定义下拉框、复杂富文本和验证码不能保证填写；这类字段会跳过或提示手动处理。
- 网站可能在 30 ms 检查之后异步清空或修改字段；插件的“填写成功”不是服务器验收结果。
- 页面仍可删除整个扩展宿主节点；Shadow DOM 解决样式冲突，不构成对恶意网页的安全边界。
- 本地存储没有额外加密。同一系统账号、浏览器配置文件或具备浏览器调试权限的软件可能读取数据。
- 撤销只针对当前页面内存中最近一次写入；它不会撤回附件、网站自动保存或最终提交。
- 开发者模式安装的扩展未经商店签名，浏览器或企业策略可能禁用本地扩展。
- `Alt+Shift+F` 可能被操作系统、输入法或其他扩展占用；用户可在 `edge://extensions/shortcuts` 检查或修改绑定。
- 简历分类是启发式处理，不能保证每种排版都正确；扫描版 PDF 当前不做 OCR。比赛/获奖年份和校园经历仍应在预览中核对；Moka 自定义下拉、日期控件和页面未提供的经历槽位仍可能需要手动处理。
- PDF 限制为 40 页、分类文件限制为 10 MB、每类经历限制为 20 条。这些限制降低异常文件造成内存或存储耗尽的风险，但不能替代对来源不明文件的谨慎处理。

## 兼容性范围

- 目标浏览器：当前版 Microsoft Edge、Google Chrome（Chromium Manifest V3）。
- 本机检测环境：Edge 153.0.4234.32。已用隔离配置实际加载并核对四标签弹窗和快捷键；用户提供的双语 DOCX、既有 DOCX 与 PDF 分类导入均通过。未写入日常 Edge 配置。
- Windows 安装助手：Windows PowerShell 5.1 或更高版本，不需要管理员权限。
- Firefox、Safari 以及移动端浏览器不在当前支持范围。

## 安装限制

Edge 不允许普通脚本静默安装未上架商店的扩展。`安装插件.cmd` 可以完成文件校验、复制、打开安装向导、打开 Edge 扩展页面和定位目标文件夹；最终开启开发人员模式、点击“加载解压缩的扩展”并选择目录，必须由用户完成。若需要真正的一次点击安装，应发布到 Microsoft Edge Add-ons 商店并使用商店安装按钮。
