# 投简历助手设计规范 · Calm Desk

适用版本：0.17.0。适用范围：扩展弹窗、网页悬浮工具、全屏工作台，以及它们的空白、加载、错误、导入预览和长内容状态。颜色的实现来源是 `design-system.css`；页面布局分别在 `popup.css`、`dashboard.css` 中定义。

## 产品原则与信息架构

弹窗处理当前网页的一次操作：选对简历、检查字段、填表、保存记录。工作台承载长时间管理：找岗位、整理申请、安排下一步。四个弹窗标签固定为“投递 / 资料 / 记录 / 经历”，位置不随数据变化。

- 首次使用：上传简历 → 核对分类 → 应用；也可手动填写。
- 已有资料：当前简历档案 → 主操作“填充当前页面” → 预览 / 撤销 → 保存岗位 / 导入网页资料 → 资料完整度。
- 记录：搜索 + 状态筛选 → 数量反馈 → 记录列表 → 公司汇总。筛选只影响显示，导出仍导出全部记录。
- 工作台：岗位发现与个人申请分开；“待处理”汇集已安排的面试、跟进和临近申请截止。

只对有证据的投递显示“已投递”。“已记录”表示保存资料，“已沟通”表示人工确认已联系。匹配分、资料完整度、岗位数都不等于已投递数。

## 布局与响应

弹窗默认 480 × 600 CSS px；小屏宽度不低于 320px。头部 76px，标签区 57px，固定在同一滚动容器内。只有一个主页面纵向滚动；导入明细文本可以独立滚动。始终预留滚动条空间，避免切换标签时按钮横向移动。低于 440px 时表单变成单列，版本号隐藏，操作名称保留。当前岗位最多展示两行且保留完整 title；历史岗位、公司和备注可换行，不只在 tooltip 中提供信息。

工作台使用白色侧边导航、浅灰背景、白色信息区。桌面侧栏 224px；760px 以下通过“打开导航”显示。表格和看板允许容器内横向滚动；页面本身不能被表格撑宽。筛选项分行呈现；重点公司目录默认折叠，减少首屏高度。对 1440、1024、760、390px 宽度检查溢出。

## 状态与交互规范

- 空白状态写出下一步，如“在岗位页点击保存当前岗位”。无搜索结果要与从未保存过数据区分。
- 所有异步操作暴露 `aria-busy` 并禁用重复触发；失败保留当前输入，显示可读错误，不声称保存成功。
- 保存岗位前读取同 URL 的已有记录，恢复状态和备注。记录始终以首次投递档案归属为准，重复手动保存不会降级已确认的投递状态。
- 岗位草稿按输入写入本机；同岗位再次打开保存框时可恢复；确认保存或取消后清除。草稿不是投递记录，也不计入投递统计。
- 导入必须先显示逐项明细，默认保留现有资料；替换与新档案都是显式选择。取消或读取失败后不能使用旧候选。
- 历史记录按 30 条渐进展示，筛选覆盖全部最多 500 条，而非只搜索首屏。数量提示说明总数、匹配数和当前显示数。
- “待处理”只依据明确安排的日期生成；面试过去后移到日程回看，过期跟进 / 未投递截止仍需处理。已结束、Offer 不生成待处理。页面打开时每分钟刷新，无系统后台通知。
- 支持 Tab、Shift+Tab、Enter、Space；弹窗标签支持左右方向键；工作台 Ctrl/Cmd+K 定位搜索。焦点清楚可见，减少动态位移；遵循 `prefers-reduced-motion`。
- 重要操作不能依赖 hover、拖动或颜色。看板岗位也可通过编辑表单选择阶段；长内容要可复制、可阅读。

网页悬浮工具保留 Shadow DOM 隔离，采用同一语义颜色和不低于 12px 的说明文字；面板宽度最多 280px，随视口收缩，并限制高度。操作结果出现时展开面板，使状态可见。手动按钮称为“记录当前岗位”，不暗示已确认投递。

## 视觉与交互验收

检查空资料、已有资料、多个档案、30 / 500 条记录、无匹配、超长中文 / 无空格 URL、成功 / 失败、导入预览、岗位草稿、窄屏、滚动后导航、键盘焦点和减少动画偏好。跨页面用相同语义颜色和字号。先检查浏览器实际渲染，再交付。模拟数据截图需明确标注为模拟，不代表真实 BOSS 在线简历适配已通过。

## 0.18.0 同步反馈

网站顶部的同步区集中显示连接、同步时间、待同步修改与恢复操作。成功状态使用正文描述和绿色标记；未连接、等待和失败都有文字说明，避免仅依赖颜色。断开保留本机记录。窄屏下操作自动换行，辅助说明不小于 12px；「完整备份」与「恢复备份」直接可见。冲突提示说明合并规则，避免把缓存成功误报为插件同步完成。
