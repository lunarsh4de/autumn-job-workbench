# 投简历助手 0.18.0

面向 Microsoft Edge 和 Google Chrome 的 Manifest V3 扩展。它识别招聘网页中的空白字段，填写本地保存的资料，并由用户核对后手动提交。

作者： [Lunarsh4de](https://github.com/lunarsh4de)

## 0.18.0 插件与网站双向同步

配套网站：https://lunarsh4de.github.io/autumn-job-workbench/ 。更新插件并刷新网站后，首次点击「连接插件」，合并此浏览器中的旧记录；之后网站打开时自动接收插件记录，关闭时记录继续留在插件中，下次打开补齐。插件右上「工作台」打开该网站。本机扩展页 `dashboard.html` 也可继续管理岗位。

- 同步公司、职位、规范化岗位链接、阶段、地点、薪资、备注、简历档案标签、截止日、跟进和面试日程；个人资料、联系方式、经历和附件不经桥接发送到网站。
- 网站修改回写插件：插件记录显示面试、笔试、Offer 等阶段。无有效链接的手填岗位只在工作台管理；有链接岗位投射到最多 500 条插件记录，工作台上限 1000 个。
- 网站使用持久待同步队列；断开、插件禁用或暂时无响应时先保存在本机，重连后重试。首次连接额外保存 `workbenchBeforeConnection` 原始快照；完整 JSON 备份包含阶段、备注和日程，恢复时合并较新记录。
- 同岗位按 ID / 去跟踪参数的 URL 去重。后台队列串行应用字段补丁；不同字段的并行修改保留，冲突字段采用后提交值并显示提示，并行备注保留双方片段（各最多 4900 字）。
- 删除同步到插件；删除标记防止旧网页和自动成功信号恢复记录。用户主动新建同链接岗位、手动重新记录或恢复备份可恢复。清空插件历史会同步清除对应看板岗位，确认框说明范围。
- 同步仅覆盖同一个浏览器配置文件，不是云备份或跨设备同步。清除网站数据会丢失尚未同步的网页修改；卸载插件或清除其数据会丢失插件记录，请定期导出备份。网页重新加载离线时能否打开取决于浏览器缓存；已打开页面可先记录。
- 只在配套 GitHub Pages 路径注册常驻消息桥，招聘网站继续按需读取当前页；岗位同步不要求账号、令牌或 GitHub Gist，不向公开岗位源上传个人记录。远端已有的可选 GitHub 私有备份保留，需用户在插件内的工作台主动登录并备份，与此同步桥独立。

参考项目、模拟用户场景与验证范围见 [同步设计说明](SYNC_DESIGN.md)。代码更新与安装包生成不代表线上 Pages 已发布，也不代表 Edge 已重新加载扩展。

## 主要功能

- 首屏先上传并解析简历，预览分类结果后再保存；一键填写姓名、电话、邮箱、城市、学历、学校、技能、主页和自我介绍，保留网页已有内容。
- 填写前预览识别结果，区分“将填写、保留现有、资料缺失、选项不匹配”。
- 明确识别到唯一简历控件时选择本地附件；已有附件、格式不符或控件不明确时跳过。
- 撤销当前页面最近一次填写；已被用户修改的字段会保留，附件和网站已接收的数据不会撤回。
- “投递 / 资料 / 记录 / 经历”四标签界面，显示资料完成度、简历状态、当前网站，记录默认显示最近 30 条并可继续加载；最多保留 500 条，记录页支持投递明细与公司汇总 CSV 导出和清空。每条自动或手动投递记录都会绑定当时使用的简历档案。
- 支持最多 12 份并行的岗位定制简历档案；每份档案独立保存基础资料、分类经历、投递附件和快捷附件设置，可在弹窗切换、重命名、删除或从简历文件导入新档案。
- 资料与附件保存在 `chrome.storage.local`，支持 JSON 备份与恢复，不接入第三方 API。
- 在岗位页按 `Alt+Shift+F` 或使用网页右键菜单即可快速填充；结果会显示在页面悬浮提示和扩展徽标中。
- 全屏“智能求职工作台”与插件共享本地数据：自动同步投递记录，并提供阶段看板、岗位列表、公司汇总、日程、搜索筛选和 CSV 导出。

## 0.17.0 界面与日常使用改版

- 弹窗与工作台使用同一套颜色、字号和状态规范：14px 正文、12px 起辅助文字，按钮和表单有明确的键盘焦点。弹窗默认 480 × 600px，窄窗口自动换为单列表单，导航固定在顶部。
- 已有简历的用户首屏显示“本次使用”的档案和填充操作；新用户继续从“上传并解析”开始。上传解析也可在“经历”页随时使用。
- 记录页支持搜索全部最多 500 条记录、按状态筛选、每次增加 30 条显示，以及直接编辑旧记录。岗位名、地点、薪资和备注可换行阅读；CSV 导出仍包含全部记录。
- 当前岗位已经保存时会显示提示；保存框会载入此前的状态、薪资和备注，避免重复填写。输入会自动保存一份本机草稿；同岗位再次打开时恢复，确认保存或取消后清除。
- 工作台新增“待处理”：集中显示未来 7 天的面试、跟进和未投递岗位的截止日期，保留逾期跟进。点击事项可调整安排；仅在工作台打开时更新，不是系统后台通知。
- 网页悬浮工具同步放大文字和按钮，反馈会展开显示；手动入口改名“记录当前岗位”，避免将收藏误认为完成投递。
- 修复岗位分类将描述中的“硬件 / Python”等技能误当职位类型的问题，优先使用岗位名称归类。
- 工作台筛选栏分行排布，重点公司目录可折叠，表格与看板在各自容器内滚动；支持 Ctrl/Cmd+K 定位搜索。
- 设计与产品说明：[设计规范](DESIGN_SYSTEM.md)、[用户场景与改版决策](PRODUCT_REVIEW.md)。参考 JobSync 的固定导航、任务分区及 JobOps 的流程组织，本次界面与功能均由本项目自行实现。

## 0.16.0 网页资料导入与跨站投递记录

- 在“投递”页点击“保存当前岗位”，核对或修改岗位、公司、独立岗位链接、地点、薪资、备注，选择“已记录 / 已沟通 / 已投递”后确认保存。适用于 BOSS 直聘和其他 HTTP(S) 招聘网页。
- BOSS 岗位详情优先识别职位和雇主，不会将平台名或推荐卡片当成当前公司；在沟通页、列表页无法确定岗位时，需要补填 `/job_detail/` 独立岗位链接。
- 同一岗位链接去掉常见跟踪参数后去重，重复保存会更新记录；已投递状态不会被后续“已记录”降级，首次保存时间和简历归属保留。多个标签页由后台排队写入。
- “已记录”进入工作台的“准备中”，“已沟通”进入新增的同名阶段，“已投递”进入已投递阶段；地点、薪资和备注一同同步，已进入面试等后续阶段的岗位不会被退回。
- 在 BOSS 打开“简历 → 在线简历”，展开资料后点击插件的“导入网页资料”。支持常见在线简历卡片中的基础资料、工作、教育、项目经历；也能读取 BOSS 和其他网站已填写的可见表单。先展示逐项明细，再由用户应用或导入为新档案，默认保留已有基础资料并追加不重复经历。
- 只读取当前页面已显示内容，不访问隐藏接口、Cookie 或未加载的历史页面，不导入打码联系方式，也不把页面内容当作附件。网站布局变动或未显示的栏目可能无法识别；可展开编辑表单后重试，或使用已有 PDF/DOCX/TXT 导入。
- 本页通过插件执行预览、填充、读取资料或保存岗位后才启用成功提示监听。刷新、新开标签页后需再次使用插件；不会后台监控所有网站。明确投递成功或发送简历成功才自动记录；“立即沟通”、聊天消息发送成功不算投递。
- 本版没有批量回溯所有网站的历史投递。已完成的投递可打开相应岗位手动补录。

验证：新增 DOM 模拟与本地数据测试覆盖 BOSS 岗位识别、卡片导入、隐藏/打码字段排除、预览确认、并发保存与工作台状态同步。实际 BOSS 在线简历页在本次检查中停留在加载状态，尚未完成登录页面的端到端验证。

## 0.15.0 岗位库、秋招管理工作台与多份岗位简历

- 弹窗右上角新增“工作台”入口，打开适合桌面长期使用的全屏管理界面。
- 插件确认成功的新投递会自动进入“已投递”阶段；已有记录首次打开时也会补齐，原始记录继续保留。
- 支持关注、准备中、已投递、笔试、面试、Offer、已结束七阶段，岗位卡片可拖动流转。
- 每个岗位可维护优先级、地点、薪资、截止日期、下一步时间、面试时间和备注。
- 总览包含核心指标、近 7 天节奏、申请漏斗、最近更新和下一步安排；另有全部岗位、公司、日程视图。
- 工作台数据保存在 `chrome.storage.local`，支持搜索、阶段筛选、优先级筛选和 UTF-8 CSV 导出。
- 导出资料备份会包含全部简历档案；导入旧版备份或新备份时默认追加为新档案，不会覆盖当前档案。

### 岗位库能力

- 新增“27届岗位库”前置发现层：支持 CSV/JSON 文件、粘贴文本和公开 HTTPS URL 批量导入，自动按链接或公司/岗位/地点去重。
- 岗位库使用 IndexedDB，单个浏览器最多保留 50,000 条，适合查看上千条公开岗位；筛选、匹配、个人投递数据均在本机完成。
- 岗位导入和公共源会自动归类为技术研发、数据算法、产品项目、设计体验、运营市场等岗位类型；地区会标准化为省份和城市，前端提供省份 → 城市级联筛选，公司改为关键字筛选，避免把数千家公司塞进下拉框。
- 岗位会标准化企业类型；来自公开源且地点在中国大陆的外企显示为“外企（中国大陆）”，工作台可单独筛选。Greenhouse 等来源会在 Action 端排除香港、新加坡和海外岗位。
- 支持岗位类型、地区、平台、匹配分、排序、岗位详情和“加入申请看板”；不再提供没有偏好时意义有限的“待评分”筛选，也不自动绕过登录、验证码、反爬或平台访问限制。
- 在“岗位来源”中维护目标岗位、技能和城市偏好，使用本地规则计算匹配分，不把简历上传到服务器；插件简历档案更新后，工作台会自动合并档案中的岗位、技能和城市关键词并重新评分。
- 工作台网页支持上传 PDF、DOCX、TXT 简历，本地解析并预览分类结果，确认后自动更新档案和岗位匹配。GitHub Pages 的普通网页模式不直接发起 OAuth；安装扩展后从扩展工作台登录 GitHub，可将个人资料、简历档案、投递记录和匹配偏好保存到自己的私有 Gist。
- GitHub Pages 可部署静态工作台；个人数据不进入仓库。仓库提供 Pages workflow，公共岗位数据可由 GitHub Actions 生成 JSON 后导入或展示。

### 自动岗位源

- [job-sources/sources.json](../job-sources/sources.json) 定义允许读取的数据源；当前直接同步腾讯、美团、特斯拉、比亚迪和吉利的校园招聘官网岗位明细，同时保留公开聚合源作为补充。
- [scripts/refresh_jobs.py](../scripts/refresh_jobs.py) 负责官网分页抓取、字段转换、过滤在招岗位和跨来源去重；Moka 官网由 [fetch_moka_jobs.mjs](../scripts/fetch_moka_jobs.mjs) 使用 Node 内置加密模块解码公开响应，不需要额外依赖。
- 大厂目录中的其他公司继续提供官网入口，但只有已验证可稳定公开读取岗位明细的官网才会进入自动 feed；不会再把“校园招聘 / 实习岗位（官方入口）”当成真实岗位。
- [pages.yml](../.github/workflows/pages.yml) 在北京时间每天 08:00、14:00 自动运行，也支持在 Actions 页面点击 `Run workflow` 一键刷新。
- 公开来源不需要个人 Token。Actions 自带的 `GITHUB_TOKEN` 只用于工作流权限；当前构建甚至不需要把 Token 交给脚本。
- Pages 打开后会读取同源 `jobs.json` 并用当前公共源结果替换旧公共岗位，过期岗位会从浏览器自己的 IndexedDB 移除；“立即同步”可手动再次刷新。

发布前需要把仓库推送到 GitHub，并在仓库 `Settings → Pages → Build and deployment` 中将 Source 设为 `GitHub Actions`。如果希望工作流自动完成首次启用，可添加名为 `PAGES_TOKEN` 的仓库 Secret（classic PAT 需要 `repo` 权限，fine-grained token 需要 Pages 写权限）；启用后后续部署使用最小权限的 `GITHUB_TOKEN`。数据源的转载和自动采集权限应由仓库维护者确认；登录态、Cookie、验证码和私人 Token 不应放入前端或公开仓库。

## 0.11.0 比赛年份与校园经历

- 文字识别新增校园经历：支持校园实践、学生工作、学生干部、社团经历、社会实践和课外活动等栏目。

## 0.9.0 简历分类与多段经历

- 工作经历、教育经历和项目经历改为结构化列表，每类最多 20 条，可在“经历”页添加、编辑和删除。
- 支持从 PDF、DOCX、TXT 本地读取简历，并自动分类基础资料及三类经历；解析结果先预览，确认后才写入。
- 导入时默认保留已有资料并追加不重复经历；勾选“替换已有经历”后才覆盖。
- 3 MB 内的 PDF/DOCX 可在确认导入时同时保存为投递附件。用于分类的文件最大 10 MB，PDF 最多解析 40 页。
- 对招聘网站已经提供的多段经历字段，按页面顺序填入第 1、2、3 段；只有一个经历大文本框时会合并全部条目。
- 备份升级到 schema v3，继续兼容 v1/v2 备份。

### 0.9.1 分类兼容修复

- 支持“英文姓名 + 中文姓名”位于同一行的双语简历，优先提取中文姓名。

- 修复“学校一行 + 专业/学位一行 + 日期一行”布局导致的学校、专业错位。

### 0.9.2 随机操作与读取稳定性

## 快速安装到 Edge

1. 解压发布包，不要直接在 ZIP 内运行文件。
2. 双击 `安装插件.cmd`。安装前会明确提示“必须开启开发人员模式”，随后校验文件、复制到固定目录，并打开 Edge 扩展页面、安装向导和目标文件夹。
3. 在 Edge 右上角点击拼图图标→“管理扩展”，再在左侧开启“开发人员模式”。
4. 点击“加载解压缩的扩展”。文件夹窗口停留在 `%LOCALAPPDATA%\ResumeQuickApply` 这一层，直接选中其中的 `Extension` 文件夹并点击“选择文件夹”，不要进入 `Extension` 内部。
5. 将“投简历助手”固定到工具栏，首次打开后填写资料并选择简历。

Edge 不允许普通脚本静默安装未上架商店的扩展，因此第 3、4 步必须由用户完成。安装助手已经将人工步骤压缩为浏览器内的一次安全确认，不需要管理员权限，也不会修改浏览器策略。真正的一键安装只能在发布到 Microsoft Edge Add-ons 商店后实现；通过注册表或企业策略强装会带来管理员权限和安全风险，本项目不采用。

更新时再次运行 `安装插件.cmd`，然后在 Edge 扩展管理页对该扩展点击“重新加载”。安装路径保持不变，扩展 ID 和本地资料不会因为复制更新而主动改变。

## 手动安装

1. Edge 打开 `edge://extensions/`；Chrome 打开 `chrome://extensions/`。
2. 开启开发人员模式，点击“加载解压缩的扩展”。
3. 选择包含 `manifest.json` 的 `resume-quick-apply` 文件夹。

安装后打开招聘网页，点击扩展图标，或按 `Alt+Shift+F`、使用网页右键菜单。插件只在这次用户操作授权的当前标签页运行，不会在所有网页后台常驻。刷新或打开新标签页后，需要再次主动触发。

## 数据和附件

资料未额外加密。备份 JSON 包含个人资料、结构化经历和完整简历附件，应像原始简历一样妥善保管。附件支持 PDF、DOC、DOCX，单份最大 3 MB；分类导入支持 PDF、DOCX、TXT，旧版 DOC 请先转换为 DOCX 或 PDF；多档案备份导入最大 64 MB。为保存多份本地附件，扩展申请 `unlimitedStorage` 本地存储权限；该权限不会增加网站访问范围。文件头校验用于发现格式不符，不能证明文件完整或无害。

简历分类使用本地规则，不会联网或上传，但不同模板的栏目和排版差异很大。分类结果不是事实认证，必须在预览和经历页中检查公司、职位、日期等字段。

选择附件并触发网页的 `change` 事件可能让网站立即上传。插件不会点击最终提交按钮；“已选择附件”不代表网站已经接收或申请已经完成。请检查页面结果后手动提交。

## 已知边界

- iframe、封闭式 Shadow DOM、自定义下拉框、复杂富文本、验证码和多步表单可能需要手动处理。
- 插件会填充网站已经存在的多段经历输入框，但不会自动点击“新增工作/教育/项目经历”按钮；槽位不足时需用户先在网站中添加。
- 扫描版或图片型 PDF 没有可提取文字，当前版本不做 OCR；请改用可复制文字的 PDF、DOCX 或 TXT。
- 网站可能在插件短时检查后异步更改字段；“已填写”不是服务器验收结果。
- 悬浮入口在当前网页被按需注入后才会出现；刷新页面后需要再次点击扩展。
- 多个简历上传框、已有附件或不支持的格式会跳过自动选择。
- 快捷键可能与系统或其他扩展冲突，可在 `edge://extensions/shortcuts` 中修改。
- 不处理验证码、自动提交或批量海投。
- 开发人员模式可能被企业策略禁用；Firefox、Safari 和移动浏览器不在当前支持范围。
