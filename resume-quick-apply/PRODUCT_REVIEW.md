# 用户流程审查与改版决策

0.18.0 增补：插件与配套网站联动的模拟用户需求、数据边界、GitHub 参考和验证范围见 [SYNC_DESIGN.md](SYNC_DESIGN.md)。新增连接状态、双向字段同步、待同步队列、删除保护与完整备份；原 0.17.0 的界面和待处理能力保留。

日期：2026-11-04；目标版本：0.17.0。

以下为基于现有代码和流程构建的产品经理走查，不是用户访谈或真实可用性实验。每条场景都有对应的实现与验证要求。

| 场景 | 原先遇到的问题 | 本次解决方式 | 可验证的结果 |
|---|---|---|---|
| 第一次打开插件，没有简历 | 不知道先做什么 | 保留显眼的上传解析入口和手填提示 | 空资料首屏出现上传；不会误显示已准备好 |
| 每天反复在岗位页打开 | 已上传后首屏仍用上传引导，填表操作在下方 | 已有资料后显示当前简历与主操作，隐藏新手上传卡 | 首屏能看到使用的档案、填充、预览、撤销 |
| 产品岗与设计岗切换简历 | 不确定本次填表使用哪份 | 投递页直接显示当前档案，提供切换入口 | 切换后即时更新名字；投递仍绑定对应档案 |
| 在几十家网站来回投 | 忘了某个岗位是否保存或投过 | 当前页已有记录提示；打开保存框载入原状态、备注 | 跟踪参数不同的同岗位仍可识别；不会被空备注覆盖 |
| 保存岗位写到一半点击网页，弹窗关了 | 岗位说明、备注等输入丢失 | 本地保存一个待完成岗位草稿 | 同岗位重开恢复；成功保存 / 取消后清除；失败保留 |
| 记录超过 30 条 | 只能看最近一页，无法快速找旧岗位 | 全量关键词搜索、状态筛选、数量反馈、显示更多 | 可以找到第 31 条之后的岗位；导出继续包含全部 |
| 想补记薪资、沟通或备注 | 列表只读、信息只在 tooltip 里 | 每条记录可编辑；备注和地点薪资直接可见 | 编辑无需回到原网页；已有记录不会新增重复条目 |
| 一周有多个截止和面试 | 时间散在岗位表单里 | “待处理”汇集未来 7 天事项和过期跟进 | 点击事项可修改日期；已结束不会继续提醒 |
| 在高分辨率笔记本或窄窗口查看 | 辅助字体太小；筛选栏塞满一行 | 统一 12px 起的辅助字号、14px 正文，筛选分行 | 长公司、备注和 URL 可读；不发生页面横向溢出 |
| 查看很长的经历表单 | 顶部标签滚出可视区域 | 弹窗头部和标签固定；稳定预留滚动条 | 可随时切换功能，按钮不因滚动条出现而跳动 |
| 打开浏览器设置页 | 无法填充仍允许点击，之后才报错 | 明确显示不可用并禁用网页操作 | 资料、记录管理仍能使用 |
| 使用键盘操作 | 不知道当前焦点；只能拖卡片 | 清楚焦点样式、方向键标签、搜索快捷键、表单改阶段 | 不依赖鼠标悬停或拖动完成常见任务 |

本轮浏览器走查还发现并修复：岗位描述里的“硬件 / Python”会抢占职位分类，现在先判断岗位名称；相对时间按日历日期计算；网页悬浮工具的手动记录按钮改名，结果面板会主动展开。

## 实现边界

没有新增 AI 评分 API、自动提交、邮箱读取或常驻网站权限。已有岗位库匹配仍是本地规则。当前 BOSS 导入依赖已展示的页面资料；本次 UI 改版不把此前停在加载页的检查升级成线上适配验证。

本轮重点是可阅读、可恢复、可检索和可跟进。浏览器内真实排版检查覆盖弹窗与工作台；DOM 测试覆盖状态转换、历史检索、草稿恢复和日期分类。验证结果记录于 `output/ui-redesign/`，不作为用户资料提交到仓库。
