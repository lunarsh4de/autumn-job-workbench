# 智能求职工作台使用指南

[在线工作台](https://lunarsh4de.github.io/autumn-job-workbench/) · [插件下载](https://github.com/lunarsh4de/autumn-job-workbench/releases/latest)

## 安装与升级

下载最新 Release 的 ZIP，解压全部内容，运行 `安装插件.cmd`。默认安装目录为 `%LOCALAPPDATA%\ResumeQuickApply\Extension`，安装向导会显示实际路径。进入 `edge://extensions/` 或 `chrome://extensions/`，开启开发者模式，加载该目录。也可直接加载解压后含 `manifest.json` 的 `ResumeQuickApply-0.19.0` 顶层目录。

已经安装的用户先导出 JSON 备份，使用同一安装目录覆盖文件，再点“重新加载”，刷新招聘页与工作台。不要卸载后重装，不要加载 ZIP 文件或源码仓库根目录。

## 找到并整理岗位

“发现岗位”先选岗位方向，再搜索职位、技能、公司，按省份、城市、公司类型、平台等多选。同组选项任一满足即可，跨组条件必须同时满足。选项数字结合其他筛选更新；已选零结果选项仍保留，可直接移除。

结果默认按公司折叠，展开后每次最多显示 50 个岗位，可以继续加载。筛选应用于具体岗位，展开后只显示满足条件的岗位。也可切换岗位列表。点岗位查看详情和来源，加入申请看板后记录准备、沟通、投递、面试等阶段；关注不等于已经投递。

公开岗位每日北京时间 08:00 / 14:00 由 GitHub Actions 更新，实际发布时间受队列和来源影响。失败来源可能保留旧数据，注意更新时间与陈旧提示。打开的网页每 30 分钟及恢复可见、联网时检查新版本。“立即同步”不会替你执行私人账号中的投递。

## 资料、账号与同步

插件中上传简历，核对解析后再应用。可为设计、产品等方向维护不同档案；填表和批量任务使用当前档案。切换档案后请重新创建并审核批次。

网站个人中心用 GitHub 登录，保存本人填写的基础资料、匹配偏好与申请管理数据。首次登录是独立空空间；“导入此浏览器的访客记录”是显式上传。简历附件不上传账号，退出后恢复访客空间。遇到版本冲突，先导出当前备份，再从云端读取。

插件同步连接**同一浏览器的访客工作台**：展开“插件连接与本机备份”，点连接。岗位、阶段、备注、日程双向同步，网站关闭时插件记录保留，下次连接补齐。账号内插件双向云同步尚未实现。网站登录成功不等于已备份插件全部简历。

## 单个岗位填写

打开招聘申请页，选好档案，点“预览填写”，检查将填写、保留现有、资料缺失、选项不匹配和附件计划。确认后填充；普通模式由你检查并点击网站提交。自动识别到明确成功结果才标记已投递；人工记录请选择实际状态。可撤销最近一次字段填充，附件或网站已经收到的数据无法撤回。

## 批量任务

在插件本机工作台右上角进入“批量投递”。先将目标岗位保存进插件申请看板，每批最多 20 个带 HTTPS 链接的岗位。网站访客岗位可连接同步；云账号空间独立，需要在插件另行添加目标岗位。

填写完整 Chat Completions API 地址（含接口路径）、模型 ID 和自己的 Key，按浏览器提示授权 API 域名。模型 ID 由你的服务商提供，当前不自动拉取模型列表。Key 本次会话保存，浏览器关闭后重新填写；“清除 Key”移除会话配置。

勾选岗位，创建批次并授予所选招聘域名权限。插件读取可识别的岗位描述并检查执行条件；在打开的招聘页补充登录、必填项和附件。插件不自动同意法律声明或处理验证码，未知页面暂停。

展开“本批交给模型的简历摘要”和每项“岗位描述与页面检查”，核对内容。勾选允许将文本交给所选模型服务，再生成文案。请求不含简历附件。逐项检查，不要保留虚构技能或项目；编辑后点“审核通过”。再次编辑需要重新审核。最后勾选真实发送 / 提交确认，执行本批已审核项。

| 状态 | 含义与下一步 |
| --- | --- |
| 待检查 / 已准备 | 尚未发送，检查页面与生成文案 |
| 待审核 / 审核通过 | 文案准备完毕，确认整批后才执行 |
| 正在提交 | 已进入不可逆动作，保留招聘页等结果 |
| 已沟通 | BOSS 对应会话有本人新增消息证据，不表示已发简历 |
| 已投递 | 受支持官网出现明确新的申请成功证据 |
| 需人工处理 | 登录、验证码、必填、附件、多步骤或未适配页面，处理后重新检查 |
| 结果不确定 | 动作可能已发生，先到网站核实，不自动重发 |
| 失败 | 查看原因，修正配置或页面条件后处理 |

BOSS 首版仅执行严格可识别的独立岗位页内已有对应聊天，或可核对的“继续沟通”同页会话。首次“立即沟通”可能触发网站默认招呼，因此需要本人操作，不自动点击；独立聊天页、跨页跳转需人工处理。Moka 首版仅执行可识别的最终申请表；完整多步骤、其他官网及网站改版需人工处理。自动执行已做模拟页面测试，尚未进行真实求职发送。来源中存在某家公司，不代表其官网支持自动投递。

任务串行执行。停止阻止后续动作，已发内容无法撤回；页面或后台中断可能暂停为结果不确定。先核实再决定人工处理，不要通过新建相同批次绕过不确定状态。

## 数据流与权限

- 简历资料与附件在插件本机保存；填表给当前招聘页，不经岗位桥上传网页。
- 登录后白名单账号资料存 Supabase，只本人可读写，附件不进入账号。
- 模型请求把本批简历文本摘要、JD 交给指定 HTTPS 服务，Key 由插件后台使用；模型输出不能更换目标或执行脚本。
- Key 仅在可信扩展会话存储，不进入备份、云账号、Secret Gist、内容脚本与日志。提 Issue、发截图不要含 Key。
- 批次按需申请站点权限，可在扩展管理页撤销。

## 常见问题

连接失败：确认插件启用、版本已刷新、浏览器配置文件一致，并回到网站访客模式。账号登录不等于插件已连接。

模型失败：核对完整地址、模型 ID、Key、余额、域名授权及服务兼容性。接口重定向会被拒绝，请用最终 HTTPS 地址；私网和本机地址不支持。

填表不完整：保留网站已有值是设计行为。自定义组件、跨域 iframe、上传失败、多步骤申请需手动处理。不要凭“填写完成”标记已投递。

升级、清理浏览器前导出 JSON 备份。Secret Gist 为独立可选备份，持有链接者可访问，不等同于仅本人可读的账号数据库。
